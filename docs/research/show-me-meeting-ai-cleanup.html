2 · Boundary rules

  • Turns: speaker/source attribution and exchanges; pauses of at least 2.5 seconds create boundaries. Eligible same-speaker sentences merge.
  • Speaker noise: weak isolated runs under 1 second can be absorbed. Supported overlap of at least 200 ms can preserve interjections.
  • Paragraphs: up to 3 complete sentences / 80 words; one long sentence can exceed that.
  • Requests: pack whole paragraphs up to 20,000 characters, within one turn.
  • Oversized paragraph: skip the whole turn, rather than split it.

Not sized by audio duration, model tokens, RAM, or GPU.

3 · What LM Studio sees

POST /chat/completions
model: your selected model
stream: false
temperature: 0.2

system: formatter instruction
user: cleanup prompt + turn text

response schema:
{ "cleaned_text": "…" }

No audio, timestamps, speaker IDs, word evidence, surrounding turns, or conversation history.

No explicit output-token cap or thinking control is sent. Server defaults still apply. Adapter request timeout: 300 seconds. The default prompt asks the model to reproduce the text, not summarize it.

Above the LM Studio budget, the service cuts out the middle. It does not split the request again. The response is then checked against the original, uncut text.

This can waste generation and trigger fallback. Bounded omissions can also pass the lexical check. The hard-coded budget does not read Gemma’s loaded context size. Raising the 20,000-character cap will not combine short turns.

6 · What happens after generation

Keep the override only if every request in that turn passes:

  • Non-empty text.
  • Protected numbers, URL-like and email-like values retained.
  • Lexical insertion/deletion ratio ≤ 0.35.
  • Output length ≤ max(1.5 × input, input + 200).

A failed turn keeps deterministic cleanup. Later turns still run. No content-rejection retry loop.

The progress counter counts planned requests, including requests skipped after a turn failure—not raw STT segments or only successful calls. Raw timing/speaker evidence is unchanged.

7 · Best changes to test

  1. Align the two budgets. Plan safe chunks; do not truncate cleanup input.
  2. Batch short turns with IDs. One request, separate validated results. Keep display turns unchanged.
  3. Skip trivial clean text carefully. Respect custom-prompt intent.
  4. Check output and reasoning settings. Bound generation with enough headroom.
  5. Stop repeated failures. Add a meeting-wide work budget.

Proposals, not measured fixes. Cross-turn batching changes the current contract. More parallel calls are not the first choice when machine load is the concern.

Scope: completed meeting AI formatting. File/URL formatting instead uses one whole-input request up to 20,000 characters, or skips AI. Meetings without timed words use one fallback turn. No application code changed; no model call or performance test run.
